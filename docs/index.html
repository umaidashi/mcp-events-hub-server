サービスのイベントを、どのAIエージェントにも届ける

MCP Events Hubは、上流サービスとクライアントエージェントの間に立つMCPサーバーです。サービスが実装するのはイベント定義の登録と、署名付きwebhookの送信の2つだけです。エージェントはハブ1か所に接続し、全サービスのイベントを1つのカタログから購読します。

サービス側の実装

MCP Eventsの重い部分は、ハブが1回だけ実装する

MCP Eventsに対応するには、購読の保存、TTL、callbackの検証、署名、再送、3つの配信方式が必要です。ハブがない場合、これをサービスごとに作ることになり、エージェントの接続先もサービスの数だけ増えます。

サービスが書くもの
  1. PUT /services/:idでイベント定義を登録する
  2. イベントが起きたら、もらったsecretで署名してPOST /services/:id/eventsに送る
ハブが引き受けるもの
  • 全サービスのイベントを<service>.<event>の名前で並べたカタログ
  • 追記専用のイベントログ。cursorはこのログの連番
  • 購読条件の照合。条件はpayloadの同名フィールドとの完全一致
  • webhook購読の保存、TTL、callbackの検証、Standard Webhooksの署名、再送
  • MCPの新旧2世代(2026-07-28と2025-11-25以前)への対応
配信方式

3つの配信方式で、特定のベンダーに依存しない

MCP Eventsのドラフト仕様にある3方式をすべて実装しています。どの方式も同じイベントログを読むので、届くイベントとcursorは同じです。

webhook

ハブが、登録されたURLへイベントごとに署名付きでPOSTします。

サーバーとして動くクライアント向け。ChatGPTが使う方式です。

push

クライアントがevents/streamを1回送り、SSEの接続を開いたまま待ちます。

公開URLを持たないローカルのエージェント向け。piの拡張の既定です。

poll

クライアントがevents/pollを定期的に送り、cursorから先を受け取ります。

長い接続を張れないクライアントでも使えます。
動かす

ローカルで、ハブとモックのサービスとpiをつなぐ

Dockerで動かす

ハブ、注文を送り続けるモックのshopサービス、拡張を入れたpiの3つを、compose.yaml1つで起動します。piには.envのANTHROPIC_API_KEYを渡します。管理画面はhttp://127.0.0.1:8787/adminで、トークンはdev-adminです。

docker compose up -d                          # ハブとshopサービス
docker compose run --rm --use-aliases client  # 拡張を読み込んだpiのTUI
docker compose run --rm --use-aliases check   # push、poll、webhookを実際のLLMで確かめる

Node.jsで動かす

依存パッケージなしで、Node.js 24以上で.tsをそのまま実行します。

  1. ハブを起動します。

    HUB_ADMIN_TOKEN=dev-admin HUB_CLIENT_TOKENS=pi:dev-client \
HUB_ALLOW_PRIVATE_CALLBACKS=1 npm start

  2. モックのshopサービスを登録し、注文イベントを送ります。

    npm run mock -- register
npm run mock -- loop 5      # 5秒ごとにランダムな注文

  3. piに拡張をインストールします。このリポジトリがそのままpiのパッケージになっています。

    pi install git:github.com/umaidashi/mcp-events-hub-server

  4. ハブの場所とトークンを渡してpiを起動し、「shop.order.createdをcustomer=aliceで購読して、届いたら金額を報告して」と頼んでください。

    MCP_EVENTS_HUB_URL=http://127.0.0.1:8787/mcp \
MCP_EVENTS_HUB_TOKEN=dev-client pi

Cloudflare WorkersとDurable Objectで動かす

同じハブを、Workerと、SQLiteストレージを持つDurable Object 1つで動かせます。構成はcloudflare.config.tsにあり、Cloudflareのcf CLIで開発とデプロイをします。

npm install
cp .dev.vars.example .dev.vars    # HUB_ADMIN_TOKENとHUB_CLIENT_TOKENS
npm run cf:dev                     # http://127.0.0.1:5173
npm run cf:deploy -- --secrets-file <秘密情報のファイル>

piの拡張はevents_catalog、events_subscribe、events_unsubscribeの3つのツールを持ちます。届いたイベントは会話に入り、エージェントの新しいターンが始まります。
